# SWPro — версия 1

SWPro — многоканальная платформа для лидеров, консультантов и их клиентов. Она объединяет персональные мини-сайты, информационные опросы, клиентскую базу, обращения, рассылки, командную структуру, подписки и оплату рабочих мест.

В этом репозитории поддерживается только версия 1 проекта.

## Основные принципы

- SWPro предоставляет программную платформу и является единственным оператором персональных данных внутри сервиса.
- Лидер и консультант получают доступ только к данным, необходимым для работы с разрешёнными им клиентами.
- Опросы SWPro имеют информационный характер: это анкеты субъективных ощущений и предпочтений, а не медицинская диагностика.
- Клиентские рассылки выполняются только при действующем согласии на информационные и рекламные сообщения.
- Команда не блокируется из-за задолженности одного участника: ограничивается только конкретное неоплаченное рабочее место.

## Роли и области доступа

### Суперадминистратор

Управляет всей платформой: лидерами, консультантами, администраторами, тарифами, бухгалтерией, способами оплаты, юридическими документами, общим контентом, шаблонами, подключениями и справкой. Может отключить 2FA пользователя только внутри формы его учётной записи.

### Лидер (`reseller`)

Управляет своей веткой, дочерними лидерами, консультантами, клиентами и командным контентом. Видит данные только своей структуры. Может рассылать сообщения своим клиентам, консультантам и лидерам в пределах разрешённой аудитории. Может создавать собственные тарифы для нижестоящей ветки в пределах лимитов своего тарифа; глобальные тарифы остаются доступны только для просмотра.

### Консультант (`manager`)

Работает только со своими клиентами, их обращениями и результатами, а также со своим контентом и рассылками. Не видит чужих консультантов, лидеров и общесистемную клиентскую базу.

### Клиент

Открывает Mini App или web-страницу по реферальной ссылке, принимает обязательные документы, заполняет анкету, проходит информационные опросы, читает материалы и связывается с закреплённым специалистом.

## Первый вход клиента

Обязательные данные анкеты:

- имя;
- фамилия;
- пол;
- возраст или дата рождения;
- город.

Телефон и email необязательны, но пользователь может указать их для связи и уведомлений.

Обязательны согласие на обработку персональных данных, пользовательское соглашение и отдельное согласие на обработку ответов опроса. Согласие на информационные и рекламные сообщения добровольное и не ограничивает основные функции сервиса.

## Web-клиенты и объединение платформ

При обычном web-входе браузер получает собственный случайный идентификатор. Это временная техническая идентичность, а не ID лидера, консультанта или администратора.

- До принятия соглашения web-профиль можно перепривязать при открытии другой реферальной ссылки.
- Web-профиль без соглашения удаляется через 3 дня.
- После соглашения неподтверждённый web-профиль хранится 5 дней для объединения с VK, Telegram или другой реальной платформой.
- После подтверждения платформы данные и история связываются с одним клиентом.
- Рабочий аккаунт лидера или консультанта не должен отображаться в клиентских списках и рассылках.

Очистка выполняется командой:

```bash
php admin/cron/cleanup-web-users.php
```

Проверка без удаления:

```bash
php admin/cron/cleanup-web-users.php --dry-run
```

## Реферальные коды

Реферальные коды глобально уникальны среди лидеров, консультантов и администраторов.

- До завершения анкеты новая реферальная ссылка может изменить выбранного лидера или консультанта.
- После подтверждения клиента новая ссылка не должна молча менять его закрепление.
- При изменении рабочего реферального кода старый код сохраняется как псевдоним и продолжает открывать правильную страницу.
- Смена кода синхронизирует связанные ссылки и не должна терять клиентов, историю или браузерные привязки.

## Преобразование клиента в рабочий аккаунт

Существующего клиента можно связать с уже созданным лидером или консультантом либо преобразовать в новый рабочий аккаунт. При этом сохраняются платформенные идентификаторы, профиль, история и связь исходной клиентской записи с рабочим местом. Для разных сущностей используются разные внутренние ID — связь хранится явно через `source_end_user_id`.

## Мини-сайты и контент

Лидер и консультант могут настраивать персональную страницу: фото, описание, контакты, материалы, продукты, опросы, акции, программы, марафоны и другие блоки.

- Общий контент задаёт суперадминистратор.
- Лидер может создать командную версию, не изменяя оригинал платформы.
- Консультант может создать личную версию только в своей области.
- Личная версия имеет приоритет над командной, командная — над общей.
- Блок «Кэшбэк и подарки» поддерживает несколько карточек, расположенных одна под другой.
- У каждой карточки есть заголовок, описание, изображение, ссылка и настраиваемый текст кнопки. Текст по умолчанию: «Оформить карту клиента».

## AI-центр и собственная база знаний

В админке предусмотрен стандартный для всех ролей помощник в правом нижнем углу. Он не зависит от тарифа, отвечает по разделу «Помощь» и утверждённым записям собственной базы знаний, учитывает роль пользователя и контекст страницы. Если подтверждённого материала нет, помощник не придумывает ответ и предлагает обратиться к человеку. Общую базу знаний редактирует только супер-администратор.

Клиентский помощник доступен в Mini App и web-интерфейсе после завершения обязательного входа. При подборе ответа он использует данные доступной области: профиль закреплённого специалиста, опубликованные материалы и продукты, результаты чек-апа, разрешённые сведения профиля и историю текущего диалога. При включённом OpenAI этот контекст передаётся без контактов, точного адреса, ID, логинов и токенов. Формулировки чек-апа остаются информационными и не превращаются в диагноз или назначение лечения.

OpenAI подключается серверным ключом `OPENAI_API_KEY` через Responses API и отдельно разрешается в настройках ИИ. Помощник админки передаёт вопрос и найденные утверждённые материалы. AI-студия по явному действию пользователя может передать тему, источник и выбранный контекст персонализации: имя, пол, возраст или дату рождения, город и содержание последнего чек-апа. Телефон, email, точный адрес, внутренние и платформенные ID, логины и токены исключаются. При ошибке внешнего API помощник админки использует собственный поиск SWPro; студия показывает ошибку и не выдаёт локальный шаблон за ответ OpenAI.

Текстовый помощник админки является стандартной функцией. Тарифы управляют голосом, обычным и персональным видео, диалогом в реальном времени, месячными лимитами и максимальной длиной ролика. Исходники AI-аватара и готовые медиа хранятся в закрытом каталоге. Для видео суперадминистратор задаёт `HEYGEN_API_KEY` или `TAVUS_API_KEY`, а владелец рабочего места указывает ID уже созданного у провайдера аватара (и ID голоса для HeyGen). Проверенный сценарий отправляется только после явного подтверждения. Существующий cron проверяет состояние задания и сохраняет готовый MP4 в SWPro.

Telegram уже отправляет MP4 методом нативного видео, а не как документ. Для VK, MAX и остальных каналов доставка должна сохранять такое же поведение с учётом возможностей их API.

Материалы, которые нельзя достоверно создать программно и которые необходимо внести вручную, перечислены в [docs/AI_CONTENT_CHECKLIST.md](docs/AI_CONTENT_CHECKLIST.md).

Суперадминистратор управляет готовностью этих материалов в разделе «Контроль базы ИИ». Там синхронизируется Docsify, утверждаются продукты и диапазоны чек-апа, задаются связи и исключения рекомендаций, разговорные сценарии и ограничения доставки видео. Изменение уже утверждённого продукта или результата автоматически снимает его допуск к ИИ до повторной проверки. Сроки хранения задаются в «Настройки ИИ», а `admin/cron/cleanup-ai-data.php` применяет их по расписанию.

### Персональная работа с клиентом

После завершённого чек-апа SWPro создаёт информационный план на 7, 14 или 30 дней из утверждённых советов по шкалам. На главной странице Mini App клиент видит блок «Сегодня для вас», текущий день, пункты плана и прогресс выполнения. Продолжительность задаётся суперадминистратором. План не является медицинским назначением.

При наличии двух завершённых прохождений одного чек-апа показывается сравнение «Было → стало» по общему результату и одинаковым шкалам. Через заданный период клиенту предлагается повторное прохождение. Изменение баллов описывается как изменение ответов анкеты, а не как медицинское улучшение или ухудшение.

### Ежедневный план лидера

Раздел «Что сделать сегодня» собирает дни рождения, новые результаты, наступивший срок повторного чек-апа, длительную неактивность и завершение клиентского плана. Для каждого повода формируется редактируемый текст. Лидер или консультант проверяет его и отправляет клиенту одной кнопкой; сообщение сохраняется в живом чате и доставляется через доступный канал. Автоматическая отправка без решения человека не выполняется.

### AI-студия и персональные материалы

AI-студия создаёт через OpenAI проверяемые черновики постов, кампаний, поздравлений, видео- и голосовых сценариев. Локальный шаблон вместо ответа ИИ не сохраняется: при недоступности OpenAI пользователь видит ошибку. Свежий результат открывается сразу под формой. Профиль клиента используется только как внутренний контекст личного материала: готовый текст не перечисляет возраст, дату рождения, пол, город, поля анкеты или результаты чек-апа. В публичных постах и описаниях продуктов клиентский контекст полностью исключается. Там же в браузере формируются две обычные PNG-карточки с персональной ссылкой и QR-кодом — горизонтальная и вертикальная. Для них доступны девять постоянных оформлений: четыре графических и пять подготовленных декоративных фонов без встроенных блоков под текст и QR-код. Фон и одна из пяти компоновок выбираются в компактных списках с миниатюрами, запоминаются в браузере и не требуют обращения к внешнему генератору изображений. Имя скачанного файла строится из реферального кода, вертикальный вариант получает суффикс `-story`. Карточки можно скачать или отправить через системное меню телефона. Сезонные темы предлагаются автоматически, но публикация и рассылка всегда требуют решения владельца.

Для голосовых сообщений предусмотрены тарифный флаг и лимит секунд. Проверенный сценарий отправляется в Audio API OpenAI только после отдельного подтверждения рядом с кнопкой. Готовый MP3 хранится закрыто, доступен владельцу рабочего места для прослушивания и скачивания и обязательно помечается как созданный ИИ. Для видео поддержаны HeyGen и Tavus; готовность проверяет уже настроенный `admin/cron/run-automations.php`.

## Опросы и результаты

Опросы собирают субъективные ответы пользователя и формируют информационный результат. Они не являются обследованием, диагнозом, медицинским заключением или назначением лечения.

Прогресс сохраняется после каждого ответа. Клиент может продолжить незавершённый опрос, посмотреть результат или пройти его заново. Закреплённый консультант и разрешённое руководство команды видят результаты в пределах своей области доступа.

## Обращения и сообщения

На Dashboard лидера и консультанта работает живой чат. Вкладка «Клиенты» показывает личные диалоги в пределах доступной клиентской базы, вкладка «Команда» — общий внутренний чат всей ветки главного лидера. Лента обновляется автоматически, поддерживает вложения и объединяет прежние обращения с новыми сообщениями Web/Mini App и подключённых платформ. Ответ сохраняется в единой истории и доставляется через доступный канал. Клиент видит тот же диалог на странице связи с консультантом.

Кнопки «Отправить клиенту» в «Что сделать сегодня» и AI-студии используют этот же чат: отправленный текст не теряется и сразу становится частью диалога.

### VK

- Для работы требуются активное сообщество, токен и настроенный Callback API.
- В VK Mini App используется системное окно `VKWebAppAllowMessagesFromGroup`.
- В обычном браузере используется web-виджет VK; если пользователь не авторизован, VK сначала предлагает войти.
- Разрешение хранится для конкретного клиента и конкретного сообщества.
- Callback-события `message_allow` и `message_deny` подтверждают или отзывают разрешение.
- Если у консультанта нет готового подключения, используется подключение его лидера; затем явно назначенное стандартное сообщество.
- При смене сообщества требуется новое разрешение. Отправка через неразрешённую группу блокируется.
- Email остаётся альтернативным каналом.

### OK

Для OK используется Bot API группы. Группа должна разрешать сообщения, пользователь — разрешить их получение, а подключение должно содержать ID группы и действующий токен.

## Рассылки

Рассылки поддерживают текст, изображение, MP4 и кнопку-ссылку.

- Консультант отправляет только своим клиентам.
- Лидер отправляет только доступным ему клиентам, консультантам и лидерам своей структуры.
- Суперадминистратор работает в системной области.
- Клиентская рассылка требует действующего маркетингового согласия.
- Для VK выбирается именно то сообщество, которому конкретный клиент дал разрешение.

## Юридические документы

В SWPro один оператор персональных данных — ИП, владелец платформы SWPro.ru. Лидеры и консультанты не становятся самостоятельными операторами только из-за реферальной ссылки или доступа к клиенту.

Публичные документы:

- политика обработки персональных данных;
- согласие на обработку персональных данных;
- согласие на обработку ответов опросов;
- согласие на информационные и рекламные сообщения;
- пользовательское соглашение;
- публичная оферта на доступ к SWPro.

Реквизиты оператора задаются в разделе «Реквизиты документов» и подставляются вместо служебных переменных. Неизвестные или пустые переменные не должны публиковаться. Даты на публичных и административных страницах отображаются в русском формате.

## Подписки и рабочие места

Тариф и общая статистика ветки остаются привязаны к главному лидеру, но оплата рассчитывается по рабочим местам:

- главный лидер оплачивает базовую часть;
- каждый нижестоящий лидер оплачивает своё место;
- каждый консультант оплачивает своё место.

Суперадминистратор управляет глобальными тарифами. Лидер может создавать и менять только свои тарифы для нижестоящей ветки, не превышая лимиты собственной подписки.

Доступны два режима:

### Предоплата за места

Период начинается с конца уже оплаченного срока. Можно оплачивать несколько месяцев вперёд. Скидки по периодам задаются в тарифе; стартовые значения — 2% за 6 месяцев и 5% за 12 месяцев.

### По факту активных

Расчётный период — календарный месяц. Первый и последний неполные месяцы считаются пропорционально дням. Счёт создаётся за прошедший месяц, срок оплаты определяется настройкой тарифа. Просрочка возникает только после окончания этого срока.

При задолженности админка остаётся доступной для просмотра счёта и оплаты. Ограничиваются Mini App, мини-сайт и клиентские функции только конкретного должника. Остальная команда продолжает работать.

## Способы оплаты

Суперадминистратор включает и настраивает методы в разделе «Подписка → Методы оплаты». Все активные способы показываются плательщикам без автоматической фильтрации по стране или валюте:

- Stripe;
- PayPal;
- ЮKassa;
- CloudPayments;
- перевод по реквизитам или другая ручная оплата.

Webhook:

```text
https://swpro.ru/api/payment_webhook.php?method=КОД
```

Коды: `stripe`, `paypal`, `yookassa`, `cloudpayments`.

## Двухфакторная защита

Для 2FA требуется приложение с поддержкой TOTP: Яндекс ID, 2FAS, Aegis, Microsoft Authenticator или аналог. QR-код нужно сканировать именно внутри такого приложения, а не обычной камерой. Суперадминистратор может отключить потерянную 2FA только в форме редактирования учётной записи пользователя; в общей таблице опасной быстрой кнопки нет.

Пользовательская документация работает на Docsify по адресу `https://swpro.ru/docs/`. Markdown-файлы хранятся в `docs/`, загружаются без отдельной сборки и доступны через боковое меню и полнотекстовый поиск. Скрипты, тема и плагины Docsify хранятся локально, поэтому справка не зависит от внешнего CDN.

Таблица `help_faq_sections` остаётся внутренним источником утверждённых ответов для AI-помощника. Публичный справочник и база ответов AI решают разные задачи и не должны автоматически перезаписывать друг друга.

## Структура проекта

- `admin/` — кабинет и бизнес-логика лидеров, консультантов и суперадминистратора;
- `admin/app/crud/` — модульная реализация CRUD;
- `api/` — авторизация клиентов, анкета, опросы, обращения, уведомления, платежи и Callback API;
- `vk-mini-app/` — общий Mini App для VK, OK, Telegram и web;
- `bot/` — Telegram и MAX;
- `database/schema.sql` — чистая актуальная схема;
- `database/seed.sql` — стартовые данные;
- `database/migrations/` — последовательные обновления рабочей базы;
- `docs/` — пользовательский справочный центр Docsify;
- `deploy/plesk/` — установка и обновление сервера;
- `index.php` — публичный мини-сайт;
- `legal.php` — публикация юридических документов.

Подробности CRUD: [admin/app/crud/README.md](admin/app/crud/README.md).

## Развёртывание

Рабочая конфигурация хранится только в `deploy/plesk/live.env`. Не создавайте параллельные `.env`, `bot/.env` или `admin/app/config/local.php`.

Установка описана в [deploy/plesk/README.md](deploy/plesk/README.md).

Обновление сервера:

```bash
cd /var/www/vhosts/swpro.ru/httpdocs
bash deploy/plesk/deploy.sh deploy/plesk/live.env
```

Скрипт получает `main`, применяет только ещё не выполненные миграции, проверяет PHP и перезапускает установленный сервис бота.

## Планировщик

```cron
*/5 * * * * cd /var/www/vhosts/swpro.ru/httpdocs && php admin/cron/run-broadcasts.php
*/15 * * * * cd /var/www/vhosts/swpro.ru/httpdocs && php admin/cron/run-automations.php
15 0 * * * cd /var/www/vhosts/swpro.ru/httpdocs && php admin/cron/run-billing.php >> storage/logs/billing-cron.log 2>&1
30 1 * * * cd /var/www/vhosts/swpro.ru/httpdocs && php admin/cron/cleanup-web-users.php >> storage/logs/web-user-cleanup.log 2>&1
```

Задачи не дублируют друг друга: рассылки, автоматические сценарии, биллинг и очистка временных web-профилей выполняют разные функции.

## Правило обновления документации

При изменении бизнес-логики необходимо одновременно обновлять:

1. `README.md` — техническую и архитектурную документацию;
2. Markdown-страницы в `docs/` — инструкции для пользователей;
3. `help_faq_sections` через `database/seed.sql` — утверждённые ответы для AI на чистой установке;
4. новую миграцию — обновление базы ответов AI на работающем сайте.
